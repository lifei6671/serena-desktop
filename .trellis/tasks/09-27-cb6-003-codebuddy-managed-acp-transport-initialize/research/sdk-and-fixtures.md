# Fixture provenance and evidence boundary

- src-tauri/tests/fixtures/codebuddy_initialize.json is the result object of CB5-002 evidence/initialize.jsonl real-cli sequence 2. Fields were already sanitized by the earlier probe. Replaying it proves local SDK compatibility only; this turn did not run a Host probe.
- src-tauri/tests/fixtures/codebuddy_early_update.jsonl reconstructs a protocol-shaped notification with synthetic sessionId fixture-session. CB5-004 evidence/host-exact-launcher-proof/wire.jsonl sequences 3/4/5 establish the source order: session/new request -> config_option_update notification -> session/new response. That sanitized source omits notification sessionId/configOptions; these fields are synthetic in this fixture, not claimed as raw Host payload. Tests preserve the observed order and add a second frame/wrong session to validate replay/isolation.
- codebuddy_acp_child.rs is a fake standalone Rust executable. It checks Job membership as its first application operation, spawns a contained long-lived fake descendant, and handles initialize only (plus a fixture-only failure trigger). No CodeBuddy installation, login, session/new or prompt is used.

SDK API sources inspected: agent-client-protocol-2.2.0/src/jsonrpc.rs (ByteStreams 6385ff; connect_with 1871ff; send_request_to_with_options 4077ff; HandleDispatchFrom 587ff; Dispatch 4977ff), jsonrpc/incoming_actor.rs (exact pending_replies.remove and EOF close), jsonrpc/transport_actor.rs (unbounded channels and raw tracing), component.rs, schema-1.9.1/src/v1/agent.rs (default capabilities).

Resource proof: only the private Requests wrapper calls SDK send_request; admission semaphore bounds request objects until completion or connection shutdown. The read guard releases at most one validated frame to SDK, awaiting handler acknowledgment; server request acknowledgment waits for actual outbound flush, bounding pending server responses. No dynamic handlers or SDK background application tasks are registered. SDK internal channels therefore cannot be filled independently of these admission limits. Unknown/duplicate responses share a stable unmatched_response_id diagnostic count with no unbounded id history. early/routed queue shares count/byte/TTL limits; route count/id length and stderr retention are separately bounded. All SDK raw tracing runs under NoSubscriber on the driver future.
